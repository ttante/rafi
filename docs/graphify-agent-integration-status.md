## QA preparation integration after handoff

- `qaBuildGate.ts` now routes depth planning/escalation, source investigation, semantic assessment and Exceptional approach challenge through `graph/preparation.ts`. This shared gate serves ordinary builds, branch worktrees, synthetic work, remediation and Manager follow-ups. Planner cwd follows the actual worktree while configuration remains project-owned; QA graph inventory follows each disposable snapshot.
- The preparation reservation remains the owning operation. Graph continuations use that operation/session and preserve read-only provider purpose, frozen requirements and independent conversations. Format repair stays response-only. Optional graph absence/drift falls back without changing depth, source obligations or publication authority.
- Provider setup, prerequisite checks and optional graph turns consume the same remaining preparation time. Deadline expiry prevents a late read/provider response from starting another turn. Snapshot cleanup runs even if prerequisites or adapter teardown fail. Cumulative graph-turn usage enters preparation accounting.
- Host-generated receipt IDs are retained on provider results and investigation evidence (`graphReceiptRefs`). Candidate-authored IDs are discarded. These optional references do not replace source citations, establish coverage, enter authoritative input freshness, or trigger contract amendment on graph-only churn.
- Preparation artifacts, events, contracts, depth decisions and retained progress propagate graph access restrictions through investigation, assessment, delivery and final review. Revoked retained evidence requires explicit source-based recovery. Staged export withholds protected preparation JSON alongside continuity/blob data. No graph-derived restrictions are registered for an empty/disabled graph scope.
- Fixed semantic-worker cleanup when worker creation completes after its deadline: the late worker is closed and receives no extraction turn.

## Gaps closed in the follow-up implementation

- **Bound interrupted exchanges:** a saved, undispatched continuation can resume only with the same frozen instruction/context, work authority and provider session. Intent/uncertain/completed records remain non-replayable. Cumulative usage, operation counts and evidence budgets survive recovery.
- **Protocol fallback:** malformed requests and exhausted rounds receive one terminal source-inspection limitation. Another request cannot recursively open repair rounds or become a business result. Existing mandatory QA parsing and handback authority remain intact.
- **Corpus rules:** pinned `ignore@7.0.5` implements Git-style `.graphifyignore` escapes, anchoring, classes, negation and excluded-parent behavior. Non-Git snapshots honor nested `.gitignore` rules. Inventory enforces an adopted word ceiling (default two million), in addition to file/byte/time ceilings. Captured source bytes must match their pinned fingerprint.
- **Accepted source-selection decision:** new adoption defaults to `sourceSelection: active-captured`. Active captured sources enter as explicitly labeled reference material, without inferred requirement approval. Source intake admits new references and removes deactivated sources; existing version pins remain unchanged, including setup retries. Existing policies without this field retain explicit source-ID selection. No URL fetch, extraction or model call occurs in source reconciliation.
- **Setup order:** the first graph build now follows final compilation and runtime-target adjustment, before planning handoff. Acceptance is persisted before compilation so interrupted setup can finish an unstarted initialization. An intended initialization is not blindly replayed. Mixed setup lazily uses the configured Planner host; AST-only setup creates no provider session.
- **Semantic budgets/accounting:** repair turns and reused chunk output count toward budgets. Returned usage and response digests survive validation failure. Deadline/cancellation independently bounds unresponsive provider promises, and worker-close failures do not become unhandled rejections. Native results also pass the total semantic-output admission limit.
- **Publication validation:** parent metadata/graph/semantic/cache checksums are verified; unexplained disappearance of unchanged-source nodes or relationships retains the previous generation.
- **Lifecycle boundaries:** merge, rebase, interrupted direct-merge completion and worktree creation/removal invalidate mutable checkout heads without deleting immutable history or starting extraction. Cleanup is bounded and abandoned staging must be at least 24 hours old and provably inactive.
- **Evidence retention:** optional evidence reservations accumulate across concurrent operations in a run (default 10 MiB), remain monotonic during retries, and never trim mandatory QA artifacts.
- **Derived evidence:** asynchronous QA/handoff storage and continuity checkpoints/events carry graph provenance. Same-session later turns inherit prior provenance, including Manager responses; revocation stops redisclosure and successor reconstruction through these paths. Multiple contributing grants remain restrictive rather than replacing one another. Graph-scoped plain diagnostic logs store digests/limitations instead of graph-derived text.
- **Transfer:** staged databases remove derived blobs and replace protected embedded continuity with explicit unavailable projections. Original digests remain references, not claims that replacement text is original evidence. Imported grants remain withheld; secure deletion removes deleted bytes from staged free pages. Live evidence is unchanged. This is regression-tested against the exported SQLite bytes.
- **QA journal compatibility:** connection-local protocol guards prevent older writers from mutating graph-continuation delivery/QA state. They do not take over preparation's schema version.
- **Bridge controls:** worker queue cancellation is prompt; the bridge requests a 512 MiB address-space limit and 300-second CPU limit, denies subprocess/fork/network operations, and reports which controls the OS actually accepted. On this macOS machine, CPU enforcement was accepted and address-space enforcement was unavailable. Reads disclose conservative collection admission instead of claiming a hard memory cap.

The existing implementation also provides graph spec/config protocols, explicit adoption, version-pinned runtime discovery/installation, immutable scoped generations, fenced publication, AST/semantic reuse, native semantic exchange, hosted turn integration, Manager requests, packaged skills, CLI commands, and the deferred-evaluation harness. See `graphify-evaluation-report.md` for observations and reproduction.
